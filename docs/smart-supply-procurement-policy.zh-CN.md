# 智能补货货源分级与抢号节奏标准

本文约束 Manager Server 自动补货在不同货源状态下的采购数量、分段抢号和重试节奏，避免“货源不足却降低总抢号量”以及配置 30 秒却被内部固定冷却拉长的问题。

## 1. 货源充足

满足实时库存可用，并有连续快速、完整交付证据时，按货源充足处理：

- 根据实际消耗速度和容量缺口决定采购时点；
- 单批采用 `1/2/3` 个的小批量渐进采购；
- 成功采购后保留策略对应的观察期，拉开账号到期时间；
- 不因为瞬时容量缺口一次性采购整批同到期账号。

## 2. 货源正常

货源能够交付但稳定性证据不足时：

- 使用中等批量；
- 继续参考消耗速度、到货时长和剩余有效期；
- 不提前囤积超出有效期内可消耗容量的账号。

## 3. 货源紧张或稀缺

近期订单取消、零交付或实现交付率明显偏低时，按货源紧张/稀缺处理：

- 首单采用当前真实容量缺口计算出的完整受限批量；
- 保留分段抢号，一轮按“基础数量、约一半、约五分之一”执行，例如 `9 → 5 → 2`；
- 小数量订单有机会在零散库存出现时成交，任何成功交付都可先缓解容量不足；
- 一轮全部失败后，按配置的自动检查间隔开启下一轮，不使用固定 60/90 秒或 2/5 分钟的本地退避；
- 通过增加单位时间内的分段轮次提高总体抢号量，而不是把每一单都放大成难以成交的超大订单；
- 单个供应商返回的 `retry_after` 只约束该订单的轮询，不应阻塞并发窗口内其他分段订单。

## 4. 配置节奏优先级

- `checkIntervalSeconds` 是缺货状态下新一轮抢号的最大本地等待时间；配置 30 秒时，普通紧急轮次不得显示或执行 60/90 秒倒计时。
- 池子接近真空、可用账号低于临界线或可用余量不足 5 分钟时，可以在配置间隔以内进一步缩短到紧急节奏。
- 成功导入少量账号但池子仍处于紧急状态时，只观察一个配置周期，再根据新快照决定是否继续分段抢号。
- 货源充足且池子不紧急时，成功订单观察期仍按策略执行，不受上述紧急节奏影响。

## 5. 容量保护

- 并发订单仍受 `maxConcurrentOrders` 约束；
- 单笔数量仍受智能缺口、`prelockMaxQuantity`、`replenishBatchSize` 和余额约束；
- 多个分段订单同时拿到库存时，最终提货继续按总容量缺口选择，避免重复支付和过量导入；
- 已成功导入的实际数量会重新参与容量计算，下一轮不得继续使用旧缺口盲目下单。
