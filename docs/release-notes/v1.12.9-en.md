## Overview

v1.12.9 fixes false Codex Accounts credential-health results: request-level model or parameter errors no longer mark healthy accounts as abnormal, fresh live authentication and quota evidence now takes precedence over stale inspections, and the credential list uses one consistent status-message presentation model.

## Highlights

### Fixes

- The Codex account pool now distinguishes unsupported-model, invalid-parameter, and context-limit request faults so healthy accounts are not incorrectly marked abnormal.
- Fresh 401, token-expiry, and hard-quota-exhaustion evidence still produces the corresponding unhealthy state, keeping genuinely unavailable accounts isolated.
- The Accounts credential list accepts both string and object status messages, keeping status labels aligned with account-pool classifications.
- The engine-fingerprint validation chain keeps its existing order and results and is unaffected by this health-classification fix.

## Upgrade Notes

- This release adds no database schema, migration, or backfill; existing account states are refreshed under the new rules when the next live request or inspection evidence arrives.
- Unsupported models and invalid parameters are request-level faults; correcting the request allows the same account to continue being used. Authentication expiry and hard quota exhaustion follow the existing handling flow.
