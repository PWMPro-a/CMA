# CPA 多供应平台采购策略

本文约束 CPA Manager Plus 在同时接入多个账号供应平台时的自动选购逻辑。目标是在保证即时可用性的前提下，综合控制价格、可消耗额度、有效期浪费、余额风险与供应商集中风险。

## 1. 平台准入

每轮采购并发查询所有已启用且凭据完整的平台，获取：

- 当前可交付库存、缺口和是否需要生产；
- 本次预计总价、单账号价格；
- 可用余额；
- 账号最短和最长剩余有效期；
- 当前平台对应的历史额度估算。

请求失败、配置不完整的平台保留在状态列表中展示错误，但不参与本轮选择。

### 1.1 平台内供应商额度门禁

对于 nvtokens 这类一个平台内包含多个商家的市场型供应源，自动采购在平台准入之后再执行“商家额度门禁”。评分维度固定为：

```text
平台 ID + 平台内 seller_token + 套餐
```

稳定身份使用 `seller_token`，下单过滤使用平台返回的 `selection_token`。商家显示名称仅用于面板展示，避免改名后丢失历史评分。

可按平台配置：

- `supplierQuotaGateEnabled`：是否启用门禁，升级默认关闭；
- `supplierQuotaMinimumM`：允许自动采购的最低单账号额度，默认 30M；
- `supplierQuotaTrialQuantity`：无历史样本商家的单次试采数量，默认 1，范围 1–5。

门禁同时作用于普通自动补池和低价抢货；人工指定平台采购继续按操作员选择执行，不经过自动门禁。

### 1.2 评分状态

每个商家和套餐有四种状态：

| 状态 | 判定 | 自动采购行为 |
| --- | --- | --- |
| `approved` | 已获得独立账号额度样本，保守评分不低于门槛 | 放行，并优先选择评分更高的商家 |
| `blocked` | 已获得独立账号额度样本，保守评分低于门槛 | 拦截 |
| `observing` | 已试采、已有导入账号或试采正在进行，但额度证据尚未形成 | 进行中的订单不重复采购；冷却结束后仍可按低价再试采 1 个 |
| `untried` | 本地无订单、账号和额度样本，平台也未标记为已采购 | 只允许一次受限试采 |

商家的 `quality_score`、活跃率和平台内历史采购次数保留用于展示，但不直接替代账号额度证据。

### 1.3 额度评分方法

评分只使用能够关联到具体导入账号的独立额度估算：

1. 自动订单绑定本次唯一商家，并将 seller、channel、selection token 写入订单；
2. 取货后将相同来源写入导入项和 Auth 文件 `cpamp_import` 元数据；
3. 额度巡检与运行时校准按 Auth 文件关联回商家；
4. 对商家最近导入的最多 20 个账号额度排序；至少 3 个样本时去掉最低和最高样本，对剩余样本取均值作为 `scoreM`；
5. `scoreM >= supplierQuotaMinimumM` 才进入 `approved`。

去掉两端极值可以降低偶发异常账号对商户评分的影响，同时保留足够样本反映商户的真实供给。面板同时展示样本数、最小值、最大值、去极值均值和导入账号数。

### 1.4 试采与并发保护

- `blocked` 是唯一永久排除状态；`approved`、`untried` 和已结束冷却的 `observing` 都进入候选；
- 已有容量样本的候选首先按成本倍率排序：`单账号价格（元） ÷ 账号容量（M）`；容量未知时才按实时单价回退，低价未知商家可以先于高成本倍率的 `approved` 商家试采；
- 试采订单数量强制缩小到 `supplierQuotaTrialQuantity`；
- 一个商家已有创建中、等待库存、取货中或导入中的试采订单时，状态立即进入 `observing`；
- 任意本地下单尝试（包括平台明确返回失败且未扣款）都会进入 `observing` 冷却，避免每轮自动补池重复轰炸同一商家；
- `observing` 默认冷却 10 分钟，给额度巡检形成证据；冷却结束仍无证据时，只允许再次试采 `supplierQuotaTrialQuantity` 个；
- 平台 `maxUnitPriceFen` 是普通补池和低价抢货共同遵守的硬上限。候选阶段先排除超价商家，精确询价后再本地复核一次，创建订单时仍把同一上限发给平台；
- 每张自动订单只绑定一个商家，估价、创建、轮询、取货、重试和补偿文件都复用相同白名单，避免一张订单混入多个商家后无法归因。

## 2. 有效额度成本

平台比较不只看单账号价格，还计算账号在有效期内真正可能被消耗的额度：

```text
预计单号额度 = 该供应商 Team 账号的已采纳额度样本
有效期内可消耗额度 = min(预计单号额度, 当前每分钟需求 × 剩余有效分钟 ÷ 本次数量)
成本倍率 = 单账号价格（元） ÷ 账号容量（M）
```

例如：18 元 ÷ 170M = 0.1059 元/M。有效期内可消耗额度继续用于容量规划；供应商容量未知时，本轮选择回退到单账号价格。

额度估算优先使用供应商维度的真实校准结果；样本不足时使用该平台的固定值或兜底值。这样可避免“单价便宜但额度低、有效期短，最终实际成本更高”的平台被错误优先。

## 3. 选择顺序

`best_available` 策略按以下顺序比较：

1. 能完整即时交付本次数量的平台；
2. 有部分现货的平台；
3. 需要等待生产的平台；
4. 余额足够且采购后不击穿配置的余额保留线；
5. 成本倍率更低；
6. 有效期内可消耗额度更高；
7. 单账号价格更低（倍率相同或容量未知时）；
8. 紧急采购时，有效期更长；
9. 同等条件下避开已有并行订单的平台，分散供应商与同批到期风险；
10. 普通采购时，有效期更长；
11. 人工配置的平台优先级作为最终兜底。

库存和余额属于硬约束，经济性比较不会让等待生产的平台压过可完整即时交付的平台，也不会让会击穿余额保留线的平台压过资金充足的平台。

## 4. 紧急与普通采购

- **紧急状态**：即时交付优先，并在经济性相同后优先更长有效期，减少刚采购即过期的风险。
- **普通状态**：继续按成本倍率采购；同等经济性下分散供应商和过期时间，避免连续采购同一批同一平台账号。
- **渐进采购**：采购数量仍由池子健康度、消耗速度、供应压力和有效期浪费策略决定；平台选择只负责在确定数量后选择本轮最合适的来源。

## 5. 面板观测项

供应平台卡片展示：

- 预计单号额度；
- 有效期内可消耗额度；
- 成本倍率（元/M）；
- 库存、总价、余额与平台错误。

运营人员应优先观察“成本倍率（元/M）”，而不是只比较账号单价；容量尚未形成时，面板会明确标记为按单价回退。
